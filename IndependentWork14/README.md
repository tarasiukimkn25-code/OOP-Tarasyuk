# Самостійна робота №15. RetryPolicy з jitter

**Тема:** Об'єктно-орієнтоване програмування (C#) | **Виконав:** Тарасюк

## Опис проєкту

`RetryPolicy` задає максимальну кількість повторів, початкову затримку та коефіцієнт jitter. `Execute<T>` приймає операцію й необов'язковий предикат `shouldRetry`. Для кожної спроби та помилки виводиться повідомлення; перед повтором друкується затримка.

Затримка розраховується за формулою з умови, де перший `retryAttempt` дорівнює нулю:

```text
delay = initialDelay * 2^retryAttempt * (1 + random * jitterFactor * 2 - jitterFactor)
```

У `Main` перша операція падає двічі й завершується успішно; друга падає до вичерпання ліміту, після чого початковий виняток передається виклику.

## Висновок

Експоненційний backoff зменшує частоту повторних звернень до сервісу, який тимчасово не відповідає. Jitter розподіляє повтори в часі, коли багато клієнтів могли збоїти одночасно. Retry має бути обмеженим і застосовуватися лише до тимчасових помилок. Його не можна безпечно повторювати для неідемпотентної операції, якщо повтор може вдруге списати гроші або створити дублікат; для таких викликів потрібен idempotency key чи інша гарантія від дублювання.
