# Лабораторна робота №15. LINQ в дії: фільтри, join, агрегації. Продуктивність (Library)

**Тема:** Об'єктно-орієнтоване програмування (C#) | **Виконав:** Тарасюк

## Опис проєкту

У цій лабораторній роботі реалізовано систему обробки даних бібліотеки **LibraryLinqApp** (Варіант 4 — Сценарій: Бібліотека), що демонструє практичне використання технології **LINQ**, різноманітні види запитів (фільтрація, об'єднання, агрегація) та аналіз їхньої продуктивності за допомогою `System.Diagnostics.Stopwatch`:

* **Фільтрація (Where):** Знаходження всіх книг Стівена Кінга (`Stephen King`), виданих після 1990 року.
* **Об'єднання (Join):** Поєднання колекцій `Book` та `Author` на основі ключів для виводу назв книг разом із іменами авторів.
* **Групування та підрахунок (GroupJoin / Count):** Підрахунок загальної кількості книг для кожного автора у бібліотеці.
* **Агрегація (Min / FirstOrDefault / OrderBy):** Пошук найстарішої книги в бібліотеці та порівняння двох підходів до пошуку мінімуму.
* **Порівняння синтаксисів:** Кожен запит реалізовано з використанням **Method Syntax** (синтаксис методів розширення) та **Query Syntax** (синтаксис запитів).

## Структура сутностей

### Класи даних:
* **`Author`** — містить властивості `Id`, `Name`, `Country`.
* **`Book`** — містить властивості `Id`, `Title`, `AuthorId`, `Year`.

## Аналіз продуктивності та висновки

1. **Method Syntax vs Query Syntax:** Обидва варіанти показують практично однакову продуктивність, оскільки компілятор C# трансформує Query Syntax у виклики методів розширення (Method Syntax).
2. **Оптимізація об'єднання (Join):** Використання оператора `join` працює набагато швидше, ніж пошук через вкладені `Where` або виклики `.First()` / `.FirstOrDefault()` всередині `Select` для кожного елемента.
3. **Ефективність агрегації:** Операція `books.Min(...)` у поєднанні з `FirstOrDefault` працює з часовою складністю $O(n)$, що значно швидше за повне сортування колекції `OrderBy(...).FirstOrDefault()` зі складністю $O(n \log n)$.
